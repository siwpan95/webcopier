1. 分配内存（需要能装下Base和Derived部分）
1. 找到合适的Derived构造函数

这种情况和无继承情况之间唯一真正的区别是，在派生类构造函数做任何实质性工作之前，必须先调用基类构造函数。Base构造函数会设置对象的Base部分，然后将控制权返回给派生类构造函数，此时派生类构造函数才可以完成自己的工作。

## 初始化基类成员

我们当前编写的Derived类有一个缺点：创建Derived对象时无法初始化m_id。如果在创建派生对象时，需要同时设置m_cost（来自对象的Derived部分）和m_id（来自对象的Base部分），该怎么办？

新程序员通常会尝试如下方式解决此问题：

```C++
class Derived: public Base
{
public:
    double m_cost {};

    Derived(double cost=0.0, int id=0)
        // 无法工作
        : m_cost{ cost }
        , m_id{ id }
    {
    }

    double getCost() const { return m_cost; }
};
```

这是一个不错的尝试，思路也几乎正确。我们确实需要向构造函数中添加另一个参数，否则C++无法知道要将m_id初始化为什么值。

然而，C++不允许在构造函数的成员初始化列表中设置继承来的成员变量。换句话说，成员变量的值只能在该变量所属类的构造函数成员初始化列表中设置。

C++为什么要这样做？答案与常量和引用变量有关。考虑如果m_id是常量会发生什么？由于常量必须在创建时用值初始化，因此基类构造函数必须在创建变量时设置其值。然而，当基类构造函数完成后，派生类构造函数的成员初始化列表随后会被执行。这样，每个派生类都有机会修改该变量，并可能更改其值！通过将变量的初始化限制在变量所属类的构造函数中，C++确保所有变量只初始化一次。

最终结果是，上面的示例无法工作，因为m_id是从Base继承来的，而成员初始化列表中只能初始化非继承而来的变量。

然而，继承而来的变量仍然可以在构造函数主体中更改其值。因此，新程序员也经常尝试这样做：

```C++
class Derived: public Base
{
public:
    double m_cost {};

    Derived(double cost=0.0, int id=0)
        : m_cost{ cost }
    {
        m_id = id;
    }

    double getCost() const { return m_cost; }
};
```

虽然在这种情况下这实际上是可行的，但如果m_id是常量或引用，则无法工作（因为常量值和引用必须在构造函数的成员初始化列表中初始化）。它也不够高效，因为m_id被设置了两次：一次在基类构造函数的成员初始化列表中，一次在派生类构造函数的主体中。最后，如果基类在构造期间需要使用该值，该怎么办？它将无法访问正确的值，因为该值直到Derived构造函数执行时才被设置（这几乎是最后发生的事情）。

那么，在创建派生类对象时，如何正确初始化m_id？

在迄今为止的所有示例中，当我们实例化Derived类对象时，Base部分都是使用默认的Base构造函数创建的。为什么它总是使用默认的Base构造函数？因为我们从来没有告诉它使用别的构造函数！

幸运的是，C++允许我们显式选择要调用哪个基类构造函数！为此，只需在派生类的成员初始化列表中添加对基类构造函数的调用：

```C++
class Derived: public Base
{
public:
    double m_cost {};

    Derived(double cost=0.0, int id=0)
        : Base{ id } // 使用 id 调用 Base(int) 构造函数!
        , m_cost{ cost }
    {
    }

    double getCost() const { return m_cost; }
};
```

更详细地说，下面是发生的情况：

1. 分配derived的内存
1. Derived(double, int) 构造函数被调用，cost = 1.3, id = 5.
1. 编译器看到，这里调用基类的构造函数 Base(int)，id = 5
1. 基类构造函数执行成员初始化列表，将 m_id 设置为 5
1. 基类构造函数的函数体执行，这里为空，不发生任何事情
1. 从基类构造函数返回
1. 派生类构造函数执行成员初始化列表，将 m_cost 设置为 1.3
1. 派生类构造函数的函数体执行，这里为空，不发生任何事情
1. 派生类构造函数返回

这看起来有点复杂，但实际上非常简单。发生的事情只是：Derived构造函数正在调用特定的Base构造函数来初始化对象的Base部分。由于m_id位于对象的Base部分，因此Base构造函数是唯一可以且应该初始化该值的构造函数。

注意，在Derived构造函数成员初始化列表中的何处调用Base构造函数并不重要——它总是首先执行。

## 将成员变量设置为private

我们已经知道了如何初始化基类成员，现在就没有必要再将成员变量保持为public。我们再次将成员变量设置为private，这也是更合适的做法。

任何人都可以访问public成员。private成员只能由同一类的成员函数访问。注意，这意味着派生类不能直接访问基类的private成员！派生类需要使用访问函数来访问基类的私有成员。

参考以下示例：

```C++
#include <iostream>

class Base
{
private: // 成员现在设置为 private
    int m_id {};
 
public:
    Base(int id=0)
        : m_id{ id }
    {
    }
 
    int getId() const { return m_id; }
};

class Derived: public Base
{
private: // 成员现在是 private
    double m_cost;

public:
    Derived(double cost=0.0, int id=0)
        : Base{ id } // 使用 id 调用 Base(int) 构造函数
        , m_cost{ cost }
    {
    }

    double getCost() const { return m_cost; }
};

int main()
{
    Derived derived{ 1.3, 5 }; // 使用 Derived(double, int) 构造函数
    std::cout << "Id: " << derived.getId() << '\n';
    std::cout << "Cost: " << derived.getCost() << '\n';

    return 0;
}
```

## 继承链

继承链中的类也以完全相同的方式工作。

```C++
#include <iostream>

class A
{
public:
    A(int a)
    {
        std::cout << "A: " << a << '\n';
    }
};

class B: public A
{
public:
    B(int a, double b)
    : A{ a }
    {
        std::cout << "B: " << b << '\n';
    }
};

class C: public B
{
public:
    C(int a, double b, char c)
    : B{ a, b }
    {
        std::cout << "C: " << c << '\n';
    }
};

int main()
{
    C c{ 5, 4.3, 'R' };

    return 0;
}
```

在这个例子中，类C从类B派生，类B又从类A派生。那么，当我们实例化类C的对象时会发生什么呢？

首先，main()调用C(int, double, char)。C构造函数调用B(int, double)。B构造函数调用A(int)。因为A没有从任何类继承，所以它是第一个要构造的类。构造A，打印值5，并返回给B。构造B，打印值4.3，并将控制权返回给C。构造C，打印值“R”，然后将控制权返回到main()。至此结束！

因此，该程序打印：

C: R

值得一提的是，构造函数只能调用其直接父类的构造函数。因此，C构造函数不能直接调用A构造函数，也不能直接向A构造函数传递参数。C构造函数只能调用B构造函数（由B负责调用A构造函数）。

## 析构函数

当派生类被销毁时，各个析构函数会以与构造相反的顺序调用。在上面的例子中，当c被销毁时，首先调用C析构函数，然后调用B析构函数和A析构函数。

> **提示:** 警告如果基类具有虚函数，则析构函数也应该是虚函数；否则在某些情况下会导致未定义行为。

---

## 总结

构造派生类时，派生类构造函数负责确定调用哪个基类构造函数。如果未指定基类构造函数，则会使用默认的基类构造函数。在这种情况下，如果找不到默认基类构造函数，编译器将报错。随后，构造会按照从最初的基类到最终派生类的顺序执行。
