```C++
int doSomething(); // 这个函数是否会抛出异常?
```

```C++
int doSomething(); // 这个函数是否会抛出异常?
```

```C++
int doSomething(); // 这个函数是否会抛出异常?
```

| 1 | intdoSomething();// 这个函数是否会抛出异常? |
| --- | --- |

在上面的示例中，doSomething()是否会引发异常？现在还不清楚。但在某些情况下，答案很重要。在前面关于异常风险和缺点的内容中，我们描述了在调用栈展开期间从析构函数中抛出异常会导致程序停止。如果doSomething()可能引发异常，那么从析构函数（或任何不希望引发异常的位置）调用它就是有风险的。尽管我们可以让析构函数处理掉doSomething()引发的异常（因此这些异常不会传播到析构函数之外），但我们必须记住这样做，并且必须确保覆盖所有可能引发的不同异常类型。

虽然注释可能有助于说明函数是否引发异常（以及会引发什么类型的异常），但文档可能会过时，而且编译器不会强制检查注释。

异常规范是一种语言机制，最初设计用于记录函数可能抛出的异常类型。虽然大多数异常规范现在都已弃用或删除，但仍有一个有用的异常规范，我们将在本课中介绍。

## noexcept说明符

在C++中，所有函数都被分类为不抛出异常或潜在抛出异常。不抛出函数承诺不会抛出调用方可见的异常。

要将函数定义为不抛出异常，可以使用noexcept说明符。为此，在函数声明中使用noexcept关键字，放在函数参数列表的右侧：

```C++
void doSomething() noexcept; // 这个函数承诺不抛出异常
```

```C++
void doSomething() noexcept; // 这个函数承诺不抛出异常
```

```C++
void doSomething() noexcept; // 这个函数承诺不抛出异常
```

| 1 | voiddoSomething()noexcept;// 这个函数承诺不抛出异常 |
| --- | --- |

注意，noexcept实际上并不会阻止函数抛出异常，也不会阻止它调用其他可能抛出异常的函数。只要noexcept函数在内部捕获并处理这些异常，且异常不会向上传播，就没有问题。

如果未处理的异常即将离开noexcept函数，则会调用std::terminate。并且，如果从noexcept函数内部调用std::terminate，调用栈展开可能会发生，也可能不会发生（取决于实现和优化），这意味着在终止之前，对象可能会被正确销毁，也可能不会。

与仅返回值不同的函数类似，不能重载仅在异常规范上不同的函数。

> **提示:** 关键点noexcept函数做出的“不抛出调用方可见异常”的承诺是一种契约承诺，而不是编译器强制执行的承诺。因此，虽然调用noexcept函数应该是安全的，但如果noexcept函数向上传播异常，就会破坏契约，从而导致程序终止！由于这个原因，最好不要让noexcept函数与异常混用，也不要让它调用可能引发异常的函数！

## noexcept函数和异常

以下程序说明了各种情况下noexcept函数和异常的行为：

```C++
#include <iostream>

class Doomed
{
public:
    ~Doomed()
    {
        std::cout << "Doomed destructed\n";
    }
};

void thrower()
{
    std::cout << "Throwing exception\n";
    throw 1;
}

void pt()
{
    std::cout << "pt (potentially throwing) called\n";
    // 调用栈展开时，这个对象会被析构
    Doomed doomed{};
    thrower();
    std::cout << "This never prints\n";
}

void nt() noexcept
{
    std::cout << "nt (noexcept) called\n";
    // 调用栈展开时，这个对象会被析构
    Doomed doomed{};
    thrower();
    std::cout << "this never prints\n";
}

void tester(int c) noexcept
{
    std::cout << "tester (noexcept) case " << c << " called\n";
    try
    {
        (c == 1) ? pt() : nt();
    }
    catch (...)
    {
        std::cout << "tester caught exception\n";
    }
}

int main()
{
    std::cout << std::unitbuf; // 每次处理后，清空buffer
    std::cout << std::boolalpha; // 将 bool 打印为 true/false
    tester(1);
    std::cout << "Test successful\n\n";
    tester(2);
    std::cout << "Test successful\n";

    return 0;
}
```

## 具有布尔参数的noexcept说明符

noexcept说明符具有可选的布尔参数。noexcept(true)等价于noexcept，表示函数不抛出异常。noexcept(false)表示函数可能会抛出异常。这些参数通常只用于模板函数，因为可以基于某些参数化值，决定创建出的模板函数是否承诺不抛出异常。

---

## 哪些函数标记为不抛出（noexcept）或潜在抛出异常

隐式不抛出的函数：

1. 析构函数

对于隐式或默认情况下不会抛出异常的函数：

1. 构造函数：默认构造、拷贝构造、移动构造
1. 赋值：拷贝、移动
1. 比较运算符（从C++20开始）

然而，如果这些函数中的任何一个调用了（显式或隐式）另一个可能引发异常的函数，则列出的函数也会被视为可能抛出异常。例如，如果类具有一个数据成员，而该数据成员的构造函数可能抛出异常，则该类的构造函数也会被视为潜在抛出异常。再举一个例子，如果拷贝赋值运算符调用了可能引发异常的拷贝操作，则拷贝赋值也可能抛出异常。

可能抛出异常的函数（如果未显式声明或默认情况下）：

1. 正常函数
1. 用户定义的构造函数
1. 用户定义的运算符

## noexcept运算符

noexcept运算符也可以在表达式内部使用。它接受表达式作为参数，并根据编译器是否认为该表达式会抛出异常，返回true或false。noexcept运算符会在编译时进行静态检查，并且不会实际计算输入表达式。

```C++
void foo() {throw -1;}
void boo() {};
void goo() noexcept {};
struct S{};

constexpr bool b1{ noexcept(5 + 3) }; // true; ints 相加不会抛出异常
constexpr bool b2{ noexcept(foo()) }; // false; foo() 会抛出异常
constexpr bool b3{ noexcept(boo()) }; // false; boo() 隐式的标记为 noexcept(false)
constexpr bool b4{ noexcept(goo()) }; // true; goo()  显式的标记为 noexcept(true)
constexpr bool b5{ noexcept(S{}) };   // true; 一个 struct 的默认构造函数默认标记为 noexcept
```

## 异常安全保证

异常安全保证是关于发生异常时函数或类行为的契约性指导。异常安全保证有四个级别：

1. 无保证——不能保证如果抛出异常会发生什么（例如，类可能处于不可用状态）
1. 基本保证——如果抛出异常，则不会泄漏内存，并且对象仍然可用，但程序的状态可能已经被修改。
1. 强保证——如果抛出异常，则不会泄漏内存，并且不会更改程序状态。这意味着函数必须完全成功，或者在失败时没有副作用。如果故障发生在最初修改任何内容之前，这很容易，但也可以通过回滚所有更改来实现，以便程序返回到故障前状态。
1. 不抛出/无失败保证——函数将始终成功，或者即使失败也不会向调用方抛出异常。异常会在函数内部被妥善处理。noexcept说明符映射到此级别的异常安全保证。

让我们更详细地看一下不抛出/无失败保证：

不抛出保证：如果函数失败，则不会抛出异常。相反，它会返回错误代码或忽略问题。在处理当前异常导致的调用栈展开期间，需要不抛出保证；例如，所有析构函数都应该具有不抛出保证（析构函数调用的任何函数也一样）。不抛出的代码示例：

1. 析构函数和内存释放/清理函数

无失败保证：函数总是能够成功完成它试图执行的操作（因此从不需要抛出异常，所以无失败是一种更强的不抛出形式）。不失败的代码示例：

1. 移动构造函数和移动赋值
1. 交换函数
1. 容器上的清除/擦除/重置功能
1. 对std::unique_ptr的操作

## 何时使用noexcept

仅仅因为代码没有显式抛出任何异常，并不意味着您就应该到处添加noexcept。默认情况下，大多数函数都可能抛出异常，因为您的函数可能会调用其他函数，而被调函数可能会抛出异常。

有几个很好的理由将函数标记为noexcept：

1. 可以安全调用的函数，如析构函数
1. noexcept函数可以让编译器执行一些在其他情况下不可用的优化。由于noexcept函数不会向函数外部抛出异常，编译器不必担心运行时进行调用栈展开，这可以让它生成更快的代码。
1. 在一些重要情况下，知道函数是noexcept可以让我们在自己的代码中实现更高效的逻辑：标准库容器（如std::vector）是noexcept感知的，并会使用noexcept运算符来确定在某些地方使用移动语义（更快）还是拷贝语义（较慢）。我们将在下一节中介绍这一点（std::move_if_noexcept）。

标准库的策略是只在不抛出异常的函数上使用noexcept。可能引发异常但由于实现原因实际上不引发异常的函数，通常不会标记为noexcept。

对于您自己的代码，始终将以下标记为noexcept：

1. 移动构造函数
1. 移动赋值运算符
1. Swap函数

请考虑将以下标记为noexcept：

1. 用于表示不抛出或无失败保证的函数（例如，记录可以从析构函数或其他noexcept函数安全调用它们）
1. 拷贝构造函数和拷贝赋值运算符（以利用优化）。
1. 析构函数。析构函数隐式为noexcept（只要所有成员变量都具有noexcept析构函数）。

> **提示:** 最佳实践如果您不确定函数是否应该具有无失败/不抛出保证，那么出于谨慎考虑，请不要用noexcept标记它。撤销noexcept会违反对用户做出的函数行为接口承诺，并且可能破坏现有代码。而为最初不是noexcept的函数添加noexcept以增强保证，通常被认为是安全的。

## 动态异常规范（可选阅读）

在C++11之前以及C++17之前，可以使用动态异常规范来代替noexcept。动态异常规范语法使用throw关键字列出函数可以直接或间接引发的异常类型：

```C++
int doSomething() throw(); // 不抛出异常
int doSomething() throw(std::out_of_range, int*); // 可能抛出 std::out_of_range 或 int*
int doSomething() throw(...); // 可能抛出任何异常
```

```C++

int doSomething() throw(std::out_of_range, int*); // 可能抛出 std::out_of_range 或 int*
int doSomething() throw(...); // 可能抛出任何异常
```

int doSomething() throw(); // 不抛出异常
int doSomething() throw(std::out_of_range, int*); // 可能抛出 std::out_of_range 或 int*
int doSomething() throw(...); // 可能抛出任何异常
