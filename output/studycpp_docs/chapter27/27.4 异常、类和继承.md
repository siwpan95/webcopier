## 当构造函数执行失败

构造函数是类中另一个适合使用异常的地方。如果构造函数由于某种原因必须失败（例如，用户传入了无效输入），只需抛出一个异常来表示对象创建失败。在这种情况下，对象的构造会被中止，并且所有类成员（在构造函数函数体执行之前已经创建和初始化）都会像往常一样被销毁。

然而，这不会调用类的析构函数（因为对象从未完成构造）。由于析构函数不会执行，因此不能依赖析构函数来清理已经分配的资源。

这带来了一个问题：如果我们在构造函数中分配了资源，然后在构造函数完成之前发生异常，应该怎么办？如何确保已经分配的资源得到适当清理？一种方法是将任何可能失败的代码包装在try块中，使用相应的catch块捕获异常并进行必要清理，然后重新引发异常（后面章节会讨论）。然而，这会增加很多混乱，并且很容易出错，特别是在类分配多个资源时。

幸运的是，有一种更好的方法。我们可以利用“即使构造函数失败，类成员也会被销毁”这一事实：如果在类成员内部（而不是构造函数本身）进行资源分配，那么当这些成员被销毁时，它们就可以完成清理。

下面是一个示例：

```C++
#include <iostream>

class Member
{
public:
	Member()
	{
		std::cerr << "Member allocated some resources\n";
	}

	~Member()
	{
		std::cerr << "Member cleaned up\n";
	}
};

class A
{
private:
	int m_x {};
	Member m_member;

public:
	A(int x) : m_x{x}
	{
		if (x <= 0)
			throw 1;
	}
	
	~A()
	{
		std::cerr << "~A\n"; // 不会被调用
	}
};

int main()
{
	try
	{
		A a{0};
	}
	catch (int)
	{
		std::cerr << "Oops\n";
	}

	return 0;
}
```

## 异常类

使用基本数据类型（如int）作为异常类型的主要问题之一是，它们本质上含义模糊。更大的问题是，当一个try块中有多个语句或函数调用时，异常的含义会产生歧义。

```C++
// 使用上面重载 operator[] 的 IntArray

try
{
    int* value{ new int{ array[index1] + array[index2]} };
}
catch (int value)
{
    // 这里捕获了什么?
}
```

## 异常和继承

由于可以将类作为异常抛出，并且类可以从其他类派生，因此我们需要考虑将继承类用作异常时会发生什么。事实证明，异常处理程序不仅会匹配特定类型的类，还会匹配从该特定类型派生的类！考虑以下示例：

```C++
#include <iostream>

class Base
{
public:
    Base() {}
};

class Derived: public Base
{
public:
    Derived() {}
};

int main()
{
    try
    {
        throw Derived();
    }
    catch (const Base& base)
    {
        std::cerr << "caught Base";
    }
    catch (const Derived& derived)
    {
        std::cerr << "caught Derived";
    }

    return 0;
}
```

## std::exception

标准库中的许多类和运算符在失败时会引发异常类。例如，如果运算符new无法分配足够的内存，则它可以抛出std::bad_alloc。失败的dynamic_cast会引发std::bad_cast。从C++20开始，有28个不同的异常类可以抛出，并且每个后续语言标准中都添加了更多异常类。

好消息是，所有这些异常类都派生自一个名为std::exception的类（在<exception>头文件中定义）。exception是一个小型接口类，旨在充当C++标准库引发的所有异常的基类。

在大多数情况下，当标准库抛出异常时，我们并不关心它是错误的分配、错误的强制转换，还是其他问题。由于所有标准库异常都是std::exception的子类，我们可以设置一个异常处理程序来捕获std::exception类型的异常，这样就可以处理所有标准库抛出的异常。很简单！

```C++
#include <cstddef> // for std::size_t
#include <exception> // for std::exception
#include <iostream>
#include <limits>
#include <string>

int main()
{
    try
    {
        // 我们的代码这里是用了标准库
        // 一个引发异常的样例
        std::string s;
        s.resize(std::numeric_limits<std::size_t>::max()); // 会触发 std::length_error 或者 内存分配异常
    }
    // 这里会 catch 住 std::exception 和所有对应的派生类
    catch (const std::exception& exception)
    {
        std::cerr << "Standard exception: " << exception.what() << '\n';
    }

    return 0;
}
```

## 从std::exception或std::runtime_error派生您自己的类

当然，您可以从std::exception派生自己的类，并重写const虚函数what()。下面是与上面相同的程序，其中ArrayException派生自std::exception。

```C++
#include <exception> // for std::exception
#include <iostream>
#include <string>
#include <string_view>

class ArrayException : public std::exception
{
private:
	std::string m_error{}; // 我们自己保存的错误

public:
	ArrayException(std::string_view error)
		: m_error{error}
	{
	}

	// std::exception::what() 返回 const char*, 需要保持一致
	const char* what() const noexcept override { return m_error.c_str(); }
};

class IntArray
{
private:
	int m_data[3] {}; // 简单起见，这里先固定长度为3

public:
	IntArray() {}
	
	int getLength() const { return 3; }

	int& operator[](const int index)
	{
		if (index < 0 || index >= getLength())
			throw ArrayException("Invalid index");

		return m_data[index];
	}

};

int main()
{
	IntArray array;

	try
	{
		int value{ array[5] };
	}
	catch (const ArrayException& exception) // 派生类优先处理
	{
		std::cerr << "An array exception occurred (" << exception.what() << ")\n";
	}
	catch (const std::exception& exception)
	{
		std::cerr << "Some other std::exception occurred (" << exception.what() << ")\n";
	}
}
```

## 异常的生命周期

当抛出异常时，被抛出的对象通常是在堆栈上分配的临时变量或局部变量。然而，异常处理过程可能会展开函数栈，导致函数的所有局部变量被销毁。那么，被抛出的异常对象如何在栈展开中存活下来呢？

当抛出异常时，编译器会将异常对象的副本复制到某块为处理异常而保留的未指定内存中（位于调用栈之外）。这样，无论堆栈是否展开、展开多少次，异常对象都会被持久保存，确保在处理异常之前一直存在。

这意味着被抛出的对象通常需要是可复制的（即使栈实际上没有展开）。高度优化的编译器可以改为执行对象移动，或者在特定情况下完全消除副本创建。

下面的示例展示了当我们尝试抛出不可复制的派生对象时会发生什么：

```C++
#include <iostream>

class Base
{
public:
    Base() {}
};

class Derived : public Base
{
public:
    Derived() {}

    Derived(const Derived&) = delete; // 不可复制
};

int main()
{
    Derived d{};

    try
    {
        throw d; // 编译失败: Derived 拷贝构造函数被删除
    }
    catch (const Derived& derived)
    {
        std::cerr << "caught Derived";
    }
    catch (const Base& base)
    {
        std::cerr << "caught Base";
    }

    return 0;
}
```
