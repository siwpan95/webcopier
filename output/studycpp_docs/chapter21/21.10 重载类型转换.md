C++允许您将一种数据类型转换为另一种。下面的示例显示了将int转换为double的过程：

```C++
int n{ 5 };
auto d{ static_cast<double>(n) }; // int 转换为 double

C++知道如何在内置数据类型之间进行转换。然而，它不知道如何转换其他用户定义的类。这正是重载类型转换运算符可以发挥作用的地方。

用户定义的转换允许将类转换为另一种数据类型。请看下面的示例：

```

这个类相当简单：它将Cents的数量保存为int，并提供访问函数来获取和设置m_cents。它还提供了一个构造函数，用于将int转换为Cents。

如果我们可以将int转换为Cents（通过构造函数），那么我们是否也可以将Cents转换回int？

如果我们已经编写了许多以int作为参数的函数，那么代码中就会充满对getCents()的调用，显得很杂乱。

为了简化操作，可以通过重载int类型转换来提供用户定义的转换。这样就可以将Cents对象直接转换为int。下面的示例展示了如何完成此操作：

```C++
class Cents
{
private:
    int m_cents{};
public:
    Cents(int cents=0)
        : m_cents{ cents }
    {
    }

    // 重载int转换
    operator int() const { return m_cents; }

    int getCents() const { return m_cents; }
    void setCents(int cents) { m_cents = cents; }
};
```

需要注意三点：

1. 
为了让自定义类可以转换为int，新增了一个成员函数“operator int()”。注意“operator”和目标类型之间有一个空格，而且这样的函数不能是static成员函数。

1. 
自定义转换函数不能有任何参数，也没有其他方式传递参数。不过这里仍然有一个隐式的“*this”参数，指向正在被转换的对象。

1. 
自定义转换函数不能写返回类型。函数名中的类型（例如上面的int）就代表返回类型。

## 显式类型转换

就像我们可以标记构造函数为explicit，以便它们不能用于隐式转换一样，出于相同的原因，也可以使重载类型转换标记为explicit。只能显式调用显式类型转换（例如，不能使用复制初始化或通过使用类似static_cast的显式转换）。

```C++
#include <iostream>

class Cents
{
private:
    int m_cents{};
public:
    Cents(int cents=0)
        : m_cents{ cents }
    {
    }

    explicit operator int() const { return m_cents; } // 现在标记为 explicit

    int getCents() const { return m_cents; }
    void setCents(int cents) { m_cents = cents; }
};

class Dollars
{
private:
    int m_dollars{};
public:
    Dollars(int dollars=0)
        : m_dollars{ dollars }
    {
    }

    operator Cents() const { return Cents { m_dollars * 100 }; }
};

void printCents(Cents cents)
{
    std::cout << static_cast<int>(cents); // explicit，因此必须使用显式类型转换
}

int main()
{
    Dollars dollars{ 9 };
    printCents(dollars);

    std::cout << '\n';

    return 0;
}
```

类型转换通常应标记为explicit。如果转换成本很低，并且目标是含义相近的用户定义类型，则可以例外。“Dollars::operator Cents()”类型转换被标记为非显式，因为没有理由不允许Dollars对象用于预期为Cents的地方。

> **提示:** 最佳实践类型转换应标记为explicit，除非要转换的类型在含义上本质相同。

## 转换构造函数与重载类型转换

重载类型转换和转换构造函数扮演着类似的角色：重载类型转换允许我们定义一个函数，将某个程序定义类型a转换为其他类型b。转换构造函数则允许我们定义一个函数，从其他类型b创建某个程序定义类型a。那么，应该在什么时候使用它们呢？

通常，转换构造函数应该优先于重载类型转换。

在一些情况下，应该使用重载类型转换：

1. 
提供到基本类型或无法修改的类的转换（因为不能为这些类型定义构造函数）。最惯用的场景是：为了让对象能够用于条件语句，提供到bool的转换。

1. 
当不希望正在构造的类型知道被转换的类型时。这有助于避免循环依赖。

对于最后一点，例如，std::string有一个构造函数，可以从std::string_view创建std::string。这意味着<string>必须包含<string_view>。如果std::string_view也有一个构造函数，可以从std::string创建std::string_view，那么<string_view>就需要包含<string>，从而导致头文件之间的循环依赖。

相反，std::string提供了一个重载类型转换，用于处理从std::string到std::string_view的转换（这没有问题，因为它已经包含了<string_view>）。而std::string_view完全不需要知道std::string的任何细节，因此不需要包含<string>。这样就避免了循环依赖。
